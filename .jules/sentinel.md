## 2025-06-04 - Fix Insecure Direct Object Reference (IDOR) in AI Request Endpoints
**Vulnerability:** The application read images belonging to AI requests using a user-provided `image_path` in `AiRequestController@cropPreview` and `ItemController@createFromAi` without verifying if the requested `AiRequest` and its associated image actually belonged to the authenticated user.
**Learning:** Even when reading from storage directly, it is crucial to perform authorization checks against the underlying resource ownership (`AiRequest->user_id === Auth::id()`), especially when file paths can be manipulated or guessed by other users.
**Prevention:** Always verify model ownership (`user_id === Auth::id()`) when querying objects via secondary identifiers or file paths, particularly when processing or serving user-specific data.
