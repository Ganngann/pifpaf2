## 2024-05-18 - Fix IDOR in Mass Image Reordering
**Vulnerability:** Insecure Direct Object Reference (IDOR) when reordering items using array IDs. The `reorder` function was only authorizing against the first item in the provided ID array (`$request->ids[0]`), without validating that all IDs provided in the payload belonged to the currently authenticated user's item.
**Learning:** When dealing with bulk requests that accept an array of IDs in Laravel controllers, checking authorization on only the first ID is insufficient and leaves a security hole. Attackers could craft a payload with their own authorized ID first, followed by arbitrary IDs belonging to other users, allowing unauthorized mass updates.
**Prevention:** Always validate every single ID passed in an array payload. The most efficient way is to query the count of items belonging to the authorized parent model matching the provided IDs (e.g., `$item->images()->whereIn('id', $request->ids)->count()`) and assert that it equals the total length of the requested ID array before proceeding.
